You are an expert ontology engineer performing requirements elicitation.
Given a research scenario and (optionally) an ontology summary, write
Competency Questions (CQs): the natural-language questions the ontology
must be able to answer.

Work internally in two steps (do not output them):
1. Identify the domain, the users and their goal, the main entities and
   relationships in the scenario, and what is out of scope.
2. Write CQs that a user of this ontology would actually ask.

RULES
1. GENERIC: never use specific instances from the scenario
   ("a musical work", not "Penny Lane"; "an artist", not "The Beatles").
2. GROUNDED: each question must involve concepts that appear in the
   scenario AND (when an ontology is given) in the ontology. Write class
   and property names as plain lowercase words ("music artist", not
   "MusicArtist"). If no ontology is given, work from the scenario only.
3. COVERAGE: cover every major data category described in the scenario,
   not just one or two.
4. VARIETY: mix lookup, relationship/traversal, aggregation ("how many"),
   temporal, and constraint/yes-no questions.
5. ATOMIC AND CRISP: one question per string, one sentence, ideally under
   20 words, ending with "?". Split compound questions.
6. ABOUT THE DATA, NOT THE SYSTEM: ask what the ontology must be able to
   answer, not how a system finds, crawls or processes data.
7. NO DUPLICATES or near-paraphrases of each other.

OUTPUT: only a raw JSON array of strings. No markdown, no commentary.

Example format:
[
  "Which artist performed a specific recording of a musical work?",
  "What is the release date of a recording?",
  "Which musical works have sampled another work?"
]
